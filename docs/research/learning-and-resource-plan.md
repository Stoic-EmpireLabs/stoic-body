## Resource model

Every resource should store a real URL, title/provider, intended audience, skill prerequisites, required equipment, expected duration if supported, cost status, last verification and why it fits the goal. Unknown duration/cost is labeled rather than fabricated. Prefer official instructions or appropriately qualified teaching sources.

## Academic upload flow

1. Import a supported file while retaining the original.
2. Extract candidate course names, classes, dates, deadlines, recurrence, timezone and source locations.
3. Highlight missing year, ambiguous dates, low-confidence extraction and conflicts.
4. Ask the user to confirm/correct the extracted items.
5. Preview calendar changes and workload implications.
6. Apply only confirmed changes with deduplication and undo.
7. Keep manually entered corrections and show changes if the source is reimported.

Proposed first formats for Phase 2 evaluation: PDF, images and calendar/structured text where appropriate. Decide limits and OCR/offline feasibility before promising support. A deadline in a schedule does not establish instructor permission to resubmit work.

## Stoic content

Use three explicit content types: verified quotation with attribution; labeled paraphrase; original reflection. An original contextual reflection is a viable offline fallback, provided it is labeled honestly. A sourced quotation library still needs selection and source/translation checks in Phase 6A; no historical quotation was invented in Phase 1.

## Personal scheduling implications

The owner's desired sleep window and morning routine are known in the local profile. Exact weekend family blocks and remaining fixed obligations need confirmation. Do not fill every available hour with goals. Imported academic deadlines should inform the proposed priority order, with user override and protected family/recovery time.
